# 入库数据分析

研究模型配置见 [团队与 Base 调研](team-research.md)：当前默认 DeepSeek 公网 `deepseek-v4-pro`，使用 `RESEARCH_LLM_API_KEY`。

分析页读取本机 `data/store.json`。采集来源勾选不再限制分析，默认保留未知评分，排除两条演示数据。点击页头「分析」进入。

## 原来为什么显示空

旧页面隐含启用了「未知分隐藏」和最低 40 分，评分又使用采集来源勾选（当时仅 feeds）。大部分原始内容 evidence 为空，被这些条件同时过滤。新分析接口 `/api/analysis` 直接读取全库，显示原始记录、项目候选和待识别线索数量，筛选条件可见、可重置。

## 实体与排序

- 相同 GitHub 仓库 URL（含正文明确链接）合并；不靠相似名字合并。一个帖子可能提及多个仓库，候选数与线索数之和可以超过原始记录数。
- GitHub / Hugging Face 等项目记录可形成开源候选；Show HN、目录中的产品是创业候选，候选不等于已核实公司。
- 无明确项目归属的新闻/社交帖子保留在「待识别线索」。详情可手动填写项目名称、官网与类型，原始文本不改动。
- 默认按原有证据加权潜力指数排序，未知排后但可见。另支持传播热度、证据覆盖和近 24 小时实测 star 每小时增长（长期持续性仍要求七天历史）。
- 现有内容并非全部与 AI 有关；候选不保证主题、质量或商业潜力，需要结合原文确认。

## 指标

| 维度 | 当前可用证据 | 仍需补齐 |
|---|---|---|
| 真实采用 | 下载、fork 等低至中置信代理 | 活跃使用、留存、下游部署、依赖方 |
| 维护交付 | push 时间 | 发布频次、issue 响应、维护者负担 |
| 增长持续性 | 至少跨七天的 star 快照 | 7/30/90 天留存、不同窗口加速度 |
| 生态扩展 | fork、已有集成证据 | 插件、依赖关系、外部贡献 |
| 需求与价值 | 已有结构化 evidence | 付费、替代流程、复购、收入质量 |
| 商业条件 | 已有结构化 evidence | 获客、毛利、成本、竞争与壁垒 |
| 传播 | 原文 URL 去重后的提及日期和平台 | 转载溯源、独立作者、真实转化 |
| 团队 | 点击后查询公开资料 | 完整任职关系、历史成果核验 |

开源权重为采用 34、交付 26、增长 22、生态 18；创业权重为需求 30、价值 28、持续采用 24、规模化 18。缺失值保持未知，现有评分器按置信度及覆盖率折减。不能把分数解释为成功概率。

传播热度独立于潜力，改为小时级：近24小时提及按6小时半衰期衰减，75% × log(1+加权提及)/log(31) + 25% × log(1+近24小时平台数)/log(9)，两项各封顶100；24小时内没有采到提及则为0。未来时间记录排除。

同时显示滚动1、6、24小时提及数，比较前一个等长窗口的数量变化。折线图按小时分桶，浏览器本地时区显示；只画实际观测时段，缺小时不补造全网零值。当前小时尚未结束。

star短期时速采用近24小时内首末真实快照差值 / 实测间隔，至少两个快照且间隔15分钟；不外推全天，也不替代长期增长持续性。存储保留相同数值在不同时间的采集，历史已丢失快照不能补造。

分析页可见时每分钟重算滚动窗口，不会启动采集或团队调研。源数据的新鲜度仍由采集任务频率决定，需在采集平台将希望跟踪的来源设为每小时或每30分钟并启用；不自动修改现有采集任务。


## 团队深度调研

打开详情和刷新分析均不触发外部调研。只有点击「深度调研」才 POST 创建队列任务，GET 只读取缓存。报告保存在 `data/research-reports/`，服务重启后的中断任务可重试。

- GitHub：公开 contributors API 最多三页/300个账号，排除 Bot，为前30位个人账号请求公开 profile（含 location / company，写入 Base 工作所在地与公开组织）。完整返回名单可展开；实际查询范围明确列出。未认证可能遇到限流，配置 `GITHUB_TOKEN` 可提升配额。贡献者不是员工或创始人名单。
- 工程团队证据分：协作广度40%、贡献分散35%、公开仓库积累25%。这是可解释启发式，不验证个人能力、履历真实性或商业能力；团队分与项目分分开。
- 创业公司：本地 `.env` 配置 `RESEARCH_LLM_API_KEY` 后可对入库材料调用 DeepSeek；额外配置 `TAVILY_API_KEY` 可检索外部公开网页。重启服务后点击研究按钮。只保留返回搜索结果中的引用，网页文本作为未信任数据。
- 创业团队按领域经验、过往交付、职能互补形成模型推断分。缺证据保持未知。只核对引用 URL 并不能保证事实正确，报告标记为部分完成，不能宣称覆盖全员。
- 尚未对真实团队运行调研，避免在用户点击之前产生请求；测试使用固定响应验证队列入口与解析。

接口参考：[GitHub contributors](https://docs.github.com/en/rest/repos/repos#list-repository-contributors)、[GitHub users](https://docs.github.com/en/rest/users/users#get-a-user)、[Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)。

当前依赖本机 Node 服务和本地存储，浏览器关闭后服务仍需运行。没有迁移到云端，也没有上传本地资料。

## 多指标初筛（2026-09-10）

分析页提供 16 个指标条件，多个条件取交集；按项目类型切换时清除不适用的条件。缺少某个指标的项目不会通过该指标的最低值筛选。来源下拉、卡片与事件列表读取后端 `sourceCatalog` 的展示名，与数据源目录对齐，YC 使用“YC AI 公司目录”。

卡片展示关键指标、初筛结论和下一步核验事项。潜力指数 ≥60 为“优先关注”，≥30 为“继续观察”，其余已评分项目为“信号偏弱”；没有评分证据为“待验证”，线索为“待识别”。这些标签是现有证据分的筛选规则，未经预测效果校准，不代表成功概率。空指标显示“待补证据”，不填零、不编造分数。

最快的初筛路径：开源看至少七天的实测日增、维护交付和真实采用线索；创业公司看需求、价值兑现和重复使用证据。累计 stars/天、目录收录和团队人数不能直接证明用户增长或收入。

每张已确认项目卡片提供“深度调研”，调用原有项目调研接口并打开对应报告；未确认线索仍先确认实体。调研仍用于公开团队与 Base 资料，不自动填充或改写潜力指数。

## 创业公司经营资料筛选（替代创业推断分）

创业公司筛选改为融资轮次、产品发布状态、盈利状态、团队人数区间与团队 Base。卡片及详情不再展示创业需求/采用推断分或综合潜力；默认按已有资料数量排序，也可按团队人数排序。开源项目保持独立指标体系。

融资读取已有报告的带引用结构化条目，优先按披露日期选取；金额保留币种及原文，不跨币种相加。团队人数、Base 读取目录或带引用的公司级调研字段，不用贡献者人数或个人地址替代。发布/盈利字段通过研究模型的 `companyFacts` 提取，仍需来源与原文匹配验证。收入、现金流、ARR、定价不直接映射为盈利；YC 目录上线与批次不映射为成立或产品发布。旧报告没有的结构化字段显示“未披露”，仅补充研究 schema，不自动启动调研。

历史报告按原始目录 URL 的实体 ID 兼容读取，官网身份更新不丢失已存融资引用。详情可展开字段来源，关闭详情后刷新已完成报告的数据。

## 自动补全与空资料展示

空经营字段默认不渲染；没有任何字段的候选保留项目入口与“待调研”提示，而不是六个空格子。没有真实观测的增长/热度区块收起。空值意为尚未收集到，不能据此断言公司没有披露。使用“仅看有经营资料”可过滤掉只有人数和 Base 的目录候选。

分析页提供按当前筛选批量调研的按钮：每次最多 5 个，使用现有公开检索与研究模型，串行队列执行；跳过正在运行及近 7 天尝试过的项目。不会在页面打开或采集入库后自动发起新调研。浏览器每 4 秒检查本批状态并重新读取分析数据，刷新页面也会恢复现有任务的状态检查。任务记录和结构化字段保存到已有研究报告；失败可在项目详情手动重试。没有配置搜索或模型时，批量接口返回配置提示，不启动空任务。
