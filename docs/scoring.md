# 评分系统说明

## 维度

开源项目：

- 真实采用 / 下游集成：低置信处理 star/download，高置信需要依赖方、集成、真实使用案例。
- 维护与交付：近期 push、release、issue 处理、文档安装路径。
- 增长持续性：多次采集形成的新增趋势；没有历史就是未知。
- 生态扩展：fork、插件、模板、模型、衍生项目。

创业公司：

- 需求成立：痛点、买方、试用、社区/媒体反复出现。
- 价值兑现：客户结果、付费、替代旧流程、案例。
- 采用持续性：留存、复用、活跃反馈、更新后的继续使用。
- 规模化条件：渠道、销售、招聘、集成、合规、部署条件。

Kimi 商业匹配另算：

- 模型调用需求。
- 技术匹配。
- 合作时机。

## 计算链路

1. 来源筛选得到当前证据池。
2. 每条证据按方法归一化到 0-100。
3. 证据有效置信度 = 人工/模型置信度 * 来源可信度 * 事实属性系数。
4. 维度分 = 该维度证据按有效置信度加权平均。
5. 维度覆盖率 = 该维度有效置信度求和后截断到 1。
6. 有效权重 = 用户配置基础权重 * 维度覆盖率。
7. 加权均分 = 维度分 * 有效权重 / 有效权重总和。
8. 潜力指数 = 加权均分 * (0.45 + 整体覆盖率 * 0.55)。

整体覆盖率低时会折减指数，避免“只剩一个高分维度”排到第一。未知不按 0 分处理。

## 边界

- 0 个来源：不计算，状态 `no_sources`。
- 权重合计为 0：不计算，状态 `zero_weight`。
- 已选来源无证据：不计算，状态 `no_evidence`。
- 证据不可归一化：该维度未知。
- 示例模式：只演示界面和计算链路，不代表真实数据。

## 当前启发式

`log` 指标使用对数归一化，适合 star、fork、points、downloads 等长尾分布。人工/模型抽取用锚点等级：none 0、weak 25、plausible 45、good 68、strong 84、proven 96。所有阈值和基础权重都是可调启发式，尚未用历史成功样本验证预测能力。
